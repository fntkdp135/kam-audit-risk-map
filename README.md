# 감사위험 지도 — 핵심감사사항·계속기업 불확실성·의견변형 실증분석

콘텐츠 산업을 **E&M 부문**(음악·방송·영화·드라마·웹툰, 78개사)과 **Game 부문**(31개사, 대조군)으로
나누어, FY2019~2024 감사보고서 **541건**에서 핵심감사사항(KAM)·계속기업 관련 중요한 불확실성·
감사의견·의견변형 근거를 추출·유형화하고, 감사보고서에 적힌 위험이 이후 그 기업에 실제로 나타난
상황과 어떻게 이어졌는지 대조한 개인 프로젝트.

## 결과 요약

| 항목 | 값 |
|---|---|
| 분석 단위 | **541 firm-year** (109개사, FY2019~2024) |
| 감사보고서 확보율 | **98.3%** (532/541) |
| 핵심감사사항 | 770개 (중복 제거 523개) → 13개 유형 |
| 분류 | 규칙 **94.4%** + LLM 보조 3.9% (미분류 1.7%) |
| 사람 표본검증 | 무작위 60건 blind 재분류 · 일치율 **94.7%** · **Cohen's κ = 0.935** |

### ① 감사인이 지목한 위험

- 최다 유형은 **수익인식(32%)**, 다음이 영업권 손상. **상위 2유형이 58%**를 차지
- 부문 간 분포 차이는 유의하나(chi2=25.23, p=0.014) 효과 크기는 작음(Cramer's V=0.220)
- 실제로 갈리는 것은 **종속·관계기업투자 평가** 한 유형뿐(Game 26.5% vs E&M 14.6%)
- 콘텐츠 산업 특유의 쟁점이 드러날 것으로 기대했으나 **수익인식·영업권 손상은 산업을 넘어 공통**

### ② 세 축은 이어지는가 — 연결은 약함

세 기재는 서로 다른 것을 말함. KAM은 감사인이 **공개적으로 밝히기로 한** 위험,
계속기업 불확실성은 **기업의 재무 상태**, 의견변형은 **감사 수행 자체가 막힌** 결과임.

- `t-1 KAM → t년 계속기업 기재`는 **검정 불가**. 계속기업 기재 38건 중 직전 연도에 KAM이
  관측되는 건이 5건뿐. **의견거절·한정의견 보고서에는 KAM을 기재하지 않으므로** 비교 자료가
  생기지 않음 — 표본 부족이 아니라 제도의 구조
- 계속기업을 매개로 두지 않고 `t년 KAM → t+1·t+2 후속 감사결과`로 재정의(293 firm-year).
  **수익인식 KAM 보유 시 후속 발생률 0.8% vs 미보유 10.8%(p=0.0002)** 로 방향이 반대 —
  정상 영업 중인 기업만 수익인식이 핵심 위험이 되므로, **KAM 유형은 예측이 아니라 현재 상태를 반영**
- **후속 결과를 하나로 합치지 않음.** 계속기업 기재 33건(관측 가능분)의 구성은
  의견변형 14 / 계속기업 재기재 10 / 제출 중단 4 / 변화 없음 5.
  셋을 합치면 "85%가 부실"처럼 읽히지만 의견변형까지 간 것은 42%이며,
  계속기업 재기재는 감사의견이 적정일 수 있어 성격이 다름

### ③ 의견변형은 왜 나오는가 — 가장 분명한 결과

6년간 의견변형 **27건**(의견거절 25 · 한정 2 · **부적정 0**). 전부 감사범위 제한.
즉 **"재무제표가 틀렸다"가 아니라 "확인할 수 없었다"**는 판정이었음.

근거 단락 전수를 추출해 사유를 다중 레이블로 분류(미분류 0건):

| 사유 | 비율 |
|---|---|
| 계속기업 불확실성의 결과 추정 불가 | 63.0% |
| **전기 의견변형 이월(기초잔액 검증 불가)** | 51.9% |
| 자산의 실재성·평가 | 51.9% |
| 특수관계자 범위·거래 확인 불가 | 33.3% |
| 재무제표·자료 자체 미제시 / 자금·투자거래 정당성 / 매출·수익 실재성 | 각 29.6% |

**의견변형은 스스로를 재생산함.** 27건이 **10개사**에서 나왔고 평균 **2.7년** 연속
(넥스쳐 6년, 레드로버·세영디앤씨 각 4년). 전기에 의견이 변형되면 당기 감사인은 기초 잔액을
검증할 방법이 없어 당기도 같은 결론에 이르며, **27건 중 63%가 직전 연도에도 의견변형** 상태였음.
→ 계속감사·신규 수임 판단에서 **전기 의견이 결정적 변수**.

## 데이터 파이프라인

감사보고서 전문은 공시유형 검색으로 받을 수 없음(공시유형 `F` 조회는 0건, 거래소
「감사보고서제출」 공시는 표지만 3,331자). **사업보고서 원문 ZIP에 첨부된 별도·연결 감사보고서**로만
확보됨.

```
src/01_build_universe.py    모집단 확정 + 사업보고서 접수번호 수집(정정본 포함 692건)
src/02_fetch_docs.py        원문 ZIP 수집·캐시
src/03_extract.py           KAM · 계속기업 · 감사의견 · 의견변형 근거 추출
src/04_classify.py          규칙기반 13유형 분류
src/05_llm_assist.py        규칙 미분류분 LLM 보조 분류(판정을 코드에 고정해 재현 가능화)
src/06_make_kappa_sample.py 사람 검증용 blind 표본 60건 생성
src/07_outcomes.py          후속 감사결과 레이블 + 계속기업 기재 전수 검토
src/08_tests.py             가설검정
src/09_kappa.py             사람 분류 대조 · Cohen's κ
src/10_opinion_basis.py     의견변형 근거 단락 사유 유형화
src/11_make_docx.py         자소서·기술노트 원고 → 워드 변환
app.py                      Streamlit 대시보드
```

### 파싱에서 부딪힌 세 가지

셋 다 **실패가 실패처럼 보이지 않았다**는 공통점이 있음.

1. **인코딩 선언이 거짓** — `encoding="utf-8"`이라 선언해놓고 실제로는 cp949인 파일이 있음.
   `errors='replace'`로 읽으면 예외 없이 한글만 깨져 키워드가 0으로 집계됨.
   → 선언을 무시하고 strict 디코딩을 utf-8 → cp949 순으로 시도
2. **서술 형식이 세 갈래** — 소제목형 / 괄호형 / 줄바꿈 없는 붙여쓰기형.
   세 형식 공통의 **"~을 핵심감사사항으로 결정하였습니다"** 선언 문장을 앵커로 삼아 해결
   (추출 항목 288개 → 1,014개)
3. **단어 중간에서 태그가 끊김** — 서식 처리 탓에 「유형자산의 실재성과 평가」가
   「형자산의…」로, 「정확성」이 「확성」으로 잘림. 문단 제목도 잘려 KAM 구간이 뒤 문단을 삼킴.
   원본 줄바꿈을 전부 지우는 방법은 문단 구분까지 없애 섹션 검출이 426→290건으로 무너져 폐기하고,
   **인접한 같은 서식 조각만 병합**하는 방식으로 해결(섹션 426→434, 깨진 항목명 23→11)

3번은 **사람 표본검증 과정에서 발견**됨. 불일치 6건 중 분류 기준 차이는 1건뿐이고 나머지는
추출 결함이었음.

### 규칙과 LLM의 역할 분담

분류 기준을 먼저 규칙으로 세워 코드가 처리하게 하면 실행할 때마다 같은 결과가 나오고
왜 그렇게 분류됐는지 설명됨. 규칙으로 잡히지 않는 잔여 건만 LLM이 원문을 읽어 분류했고,
**그 판정을 코드에 표로 고정**해 재현 가능하게 만들었음(자동 API 호출 구조가 아님).
LLM 분류 중 반복되는 패턴(장기선급금·미니멈개런티 등 콘텐츠 제작비 계정)은 다시 규칙으로 옮겨
처리율을 92.8% → 94.4%로 올림.

## 한계

- **후속 결과는 프록시** — 부도·상장폐지 자료가 아니라 이듬해 감사보고서 상태.
  M&A로 인한 제출 중단이 섞일 수 있음
- **부적정 0건**은 이 표본에서의 관측이며 일반 명제가 아님
- **Game 부문은 업종코드 5821 접두로만 정의** — 3자리 582는 게임과 시스템·응용 소프트웨어를
  구분할 수 없어 제외했고 그 안에 엔씨소프트·컴투스홀딩스·넥슨게임즈가 포함됨
- **KAM은 기업 안에 중첩** — 항목 단위 검정은 독립성 가정을 어기므로 기업 단위 재검정을 병기했고
  결과가 갈리는 항목은 확정하지 않음
- **κ 표본 60건** — 신뢰구간이 넓고, 추출기 수정 후 재측정은 미수행
  (표본 60건 중 50건 존속·분류 변경 0건·존속분 κ=0.924)
- **항목명 추출 실패 11건**이 남아 화면에서는 대체 문구로 표시
- **FY2019는 다른 연도와 비교 불가** — 핵심감사사항 단계 도입기(검출률 44.4%)
- **감사인별 성과 비교는 수행하지 않음** — 감사인마다 클라이언트 구성이 달라 통제 없는 비교는
  감사 품질이 아니라 클라이언트 구성을 재게 됨

## 실행

```bash
pip install -r requirements.txt
streamlit run app.py
```

원문을 재수집하려면 `.env`에 `DART_API_KEY`가 필요함(대시보드 실행에는 불필요).
`data/raw/`(약 194MB)는 재수집 가능하므로 저장소에서 제외했음.
