# 감사위험 지도 — 핵심감사사항·계속기업 불확실성·의견변형 실증분석

**대시보드**: https://kam-audit-risk-map-nqqdbmneumgxz3miqgxv2d.streamlit.app/

콘텐츠 산업을 **E&M 부문**(음악·방송·영화·드라마·웹툰, 78개사)과 **Game 부문**(31개사, 대조군)으로
나누어, FY2019~2025 감사보고서 **636 firm-year**에서 핵심감사사항(KAM)·계속기업 관련 중요한 불확실성·
감사의견·의견변형 근거를 추출·유형화하고, 감사보고서에 적힌 위험이 이후 그 기업에 실제로 나타난
상황과 어떻게 이어졌는지 대조한 개인 프로젝트.

## 결과 요약

| 항목 | 값 |
|---|---|
| 분석 단위 | **636 firm-year** (109개사, FY2019~2025) |
| 감사보고서 확보율 | **98.4%** (626/636) |
| 핵심감사사항 | **466개** (firm-year당 연결 우선 1개 문서) → 13개 유형 |
| 분류 | 규칙 **93.8%** + LLM 보조 5.5% (미분류 0.6%) |
| 사람 표본검증 | 무작위 60건 blind 재분류 · **Cohen's κ = 0.935** (FY2019~2024 구간 대상. 파이프라인 정리 후 존속 42건 기준 0.911) |

### ① 감사인이 지목한 위험

- 최다 유형은 **수익인식(38.8%)**, 다음이 영업권 손상. **상위 2유형이 71.0%**를 차지
- **부문 간 분포 차이는 유의하지 않음**(chi2=19.06, p=0.087). 수익인식 39.3% vs 37.4%,
  영업권 손상 30.2% vs 38.3%로 두 부문의 구조가 사실상 같음
- E&M 부문 특유의 회계쟁점이 드러날 것으로 기대했으나 **Game 부문과 다르지 않았음**

> **연결·별도 이중 계상을 제거한 결과다.** 초기에는 firm-year마다 연결·별도 감사보고서를
> 둘 다 세어 "Game 부문이 종속·관계기업투자 평가에 편중(26.5% vs 14.6%, p=0.002)"이라는
> 결과가 나왔으나, 이는 산업 차이가 아니라 문서 구성의 차이였다. 종속·관계기업투자 유형의
> **85%가 별도보고서**에서 나오고 영업권 손상은 **69.5%가 연결**에서 나오기 때문이다.
> 같은 사건을 연결에서는 영업권, 별도에서는 종속기업투자주식으로 부르는 것이다.
> **연결 우선(연결 미작성 기간만 별도)** 으로 firm-year당 한 문서만 채택하자 부문 차이가 사라졌다.

### ② 세 축은 이어지는가 — 연결은 약함

세 기재는 서로 다른 것을 말함. KAM은 감사인이 **공개적으로 밝히기로 한** 위험,
계속기업 불확실성은 **기업의 재무 상태**, 의견변형은 **감사 수행 자체가 막힌** 결과임.

- `t-1 KAM → t년 계속기업 기재`는 **검정 불가**. 계속기업 기재 42건 중 직전 연도에 KAM이
  관측되는 건이 5건뿐. **의견거절·한정의견 보고서에는 KAM을 기재하지 않으므로** 비교 자료가
  생기지 않음 — 표본 부족이 아니라 제도의 구조
- 계속기업을 매개로 두지 않고 `t년 KAM → t+1·t+2 후속 감사결과`로 재정의(355 firm-year).
  **수익인식 KAM 보유 시 후속 발생률 1.9% vs 미보유 9.5%(p=0.003)** 로 방향이 반대 —
  정상 영업 중인 기업만 수익인식이 핵심 위험이 되므로, **KAM 유형은 예측이 아니라 현재 상태를 반영**(기업 단위 5.1% vs 28.6%, p=0.004)
- **후속 결과를 하나로 합치지 않음.** 계속기업 기재 37건(관측 가능분)의 구성은
  의견변형 19 / 계속기업 재기재 9 / 제출 중단 4 / 변화 없음 5.
  셋을 합치면 "86%가 부실"처럼 읽히지만 의견변형까지 간 것은 51%이며,
  계속기업 재기재는 감사의견이 적정일 수 있어 성격이 다름

### ③ 의견변형은 왜 나오는가 — 가장 분명한 결과

7년간 의견변형 **34건**(의견거절 31 · 한정 3 · **부적정 0**). 전부 감사범위 제한.
즉 **"재무제표가 틀렸다"가 아니라 "확인할 수 없었다"**는 판정이었음.

근거 단락 전수를 추출해 사유를 다중 레이블로 분류(미분류 0건):

| 사유 | 비율 |
|---|---|
| 계속기업 불확실성의 결과 추정 불가 | 61.8% |
| 자산의 실재성·평가 | 55.9% |
| **전기 의견변형 이월(기초잔액 검증 불가)** | 47.1% |
| 재무제표·자료 자체 미제시 | 32.4% |
| 매출·수익의 실재성 / 자금·투자거래의 정당성 | 각 29.4% |
| 특수관계자 범위·거래 확인 불가 | 26.5% |

**의견변형은 스스로를 재생산함.** 34건이 **12개사**에서 나왔고 평균 **2.8년** 연속
(넥스쳐 7년, 레드로버 5년, 아이에이치큐·세영디앤씨 각 4년). 전기에 의견이 변형되면 당기 감사인은
기초 잔액을 검증할 방법이 없어 당기도 같은 결론에 이르며, **34건 중 65%가 직전 연도에도 의견변형** 상태였음.
→ 계속감사·신규 수임 판단에서 **전기 의견이 결정적 변수**.

## 데이터 파이프라인

감사보고서 전문은 공시유형 검색으로 받을 수 없음(공시유형 `F` 조회는 0건, 거래소
「감사보고서제출」 공시는 표지만 3,331자). **사업보고서 원문 ZIP에 첨부된 별도·연결 감사보고서**로만
확보됨.

```
src/01_build_universe.py    모집단 확정 + 사업보고서 접수번호 수집(정정본 포함 806건)
src/02_fetch_docs.py        원문 ZIP 수집·캐시
src/03_extract.py           KAM · 계속기업 · 감사의견 · 의견변형 근거 추출
src/04_classify.py          규칙기반 13유형 분류
src/05_llm_assist.py        규칙 미분류분 LLM 보조 분류(판정을 코드에 고정해 재현 가능화)
src/06_make_kappa_sample.py 사람 검증용 blind 표본 60건 생성
src/07_outcomes.py          후속 감사결과 레이블 + 계속기업 기재 전수 검토
src/08_tests.py             가설검정
src/09_kappa.py             사람 분류 대조 · Cohen's κ
src/10_opinion_basis.py     의견변형 근거 단락 사유 유형화
src/11_make_docx.py         자소서·기술노트 원고 → 워드 변환
app.py                      Streamlit 대시보드
```

### 파싱에서 부딪힌 세 가지

셋 다 **실패가 실패처럼 보이지 않았다**는 공통점이 있음.

1. **인코딩 선언이 거짓** — `encoding="utf-8"`이라 선언해놓고 실제로는 cp949인 파일이 있음.
   `errors='replace'`로 읽으면 예외 없이 한글만 깨져 키워드가 0으로 집계됨.
   → 선언을 무시하고 strict 디코딩을 utf-8 → cp949 순으로 시도
2. **서술 형식이 세 갈래** — 소제목형 / 괄호형 / 줄바꿈 없는 붙여쓰기형.
   세 형식 공통의 **"~을 핵심감사사항으로 결정하였습니다"** 선언 문장을 앵커로 삼아 해결
3. **단어 중간에서 태그가 끊김** — 서식 처리 탓에 「유형자산의 실재성과 평가」가
   「형자산의…」로, 「정확성」이 「확성」으로 잘림. 문단 제목도 잘려 KAM 구간이 뒤 문단을 삼킴.
   원본 줄바꿈을 전부 지우는 방법은 문단 구분까지 없애 섹션 검출이 426→290건으로 무너져 폐기하고,
   **인접한 같은 서식 조각만 병합**하는 방식으로 해결
4. **연결·별도 이중 계상** — firm-year마다 두 문서를 모두 처리해 같은 사건이 두 번 세어짐.
   부문별 유형 분포를 왜곡했음 → **연결 우선 1개 문서만 채택**

3번은 **사람 표본검증 과정에서 발견**됨. 불일치 6건 중 분류 기준 차이는 1건뿐이고 나머지는
추출 결함이었음.

### 규칙과 LLM의 역할 분담

분류 기준을 먼저 규칙으로 세워 코드가 처리하게 하면 실행할 때마다 같은 결과가 나오고
왜 그렇게 분류됐는지 설명됨. 규칙으로 잡히지 않는 잔여 건만 LLM이 원문을 읽어 분류했고,
**그 판정을 코드에 표로 고정**해 재현 가능하게 만들었음(자동 API 호출 구조가 아님).
LLM 분류 중 반복되는 패턴(장기선급금·미니멈개런티 등 콘텐츠 제작비 계정)은 다시 규칙으로 옮겨
처리율을 올림(최종 93.8%).

## 한계

- **후속 결과는 프록시** — 부도·상장폐지 자료가 아니라 이듬해 감사보고서 상태.
  M&A로 인한 제출 중단이 섞일 수 있음
- **부적정 0건**은 이 표본에서의 관측이며 일반 명제가 아님
- **Game 부문은 업종코드 5821 접두로만 정의** — 3자리 582는 게임과 시스템·응용 소프트웨어를
  구분할 수 없어 제외했고 그 안에 엔씨소프트·컴투스홀딩스·넥슨게임즈가 포함됨
- **KAM은 기업 안에 중첩** — 항목 단위 검정은 독립성 가정을 어기므로 기업 단위 재검정을 병기했고
  결과가 갈리는 항목은 확정하지 않음
- **κ 표본 60건** — 신뢰구간이 넓음. 표본은 **FY2019~2024 모집단에서** 추출한 것이라
  FY2025 항목은 검증 대상에 포함되지 않았음(검증 범위 명시).
  파이프라인 정리 후 표본 60건 중 42건 존속·분류 변경 0건·존속분 κ=0.911
- **항목명 추출 실패**가 일부 남아 화면에서는 대체 문구로 표시
- **FY2019는 다른 연도와 비교 불가** — 핵심감사사항 단계 도입기(검출률 45.7% vs 다른 해 60~81%)
- **감사인별 성과 비교는 수행하지 않음** — 감사인마다 클라이언트 구성이 달라 통제 없는 비교는
  감사 품질이 아니라 클라이언트 구성을 재게 됨

## 실행

```bash
pip install -r requirements.txt
streamlit run app.py
```

원문을 재수집하려면 `.env`에 `DART_API_KEY`가 필요함(대시보드 실행에는 불필요).
`data/raw/`(약 194MB)는 재수집 가능하므로 저장소에서 제외했음.
